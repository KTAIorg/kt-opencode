# KT 输入校正

> **一句话**：先校正，再理解。语音和打字里的 KT 组织词，按词表静默换成用户真正想说的词。

## 所有权

- 这是**输入层**能力，不是人事别名（那是 `people-ops-resolver`），也不是产品命名对外文案（Kito 对外名仍看各仓库 AGENTS）。
- 词表源：`references/glossary.md`。新的稳定口误只追加词表，不写进对话记忆了事。
- 组织级源仓库是 `KTAIorg/kt-agent-skills`。本目录是 Kito 仓库内的工作副本，方便 Cloud Agent 加载。

## 何时用

**每条用户消息都用**，尤其是语音转写之后。用户不必说「请校正」。

也在用户明确要求时用：

- 「帮我写一个输入校正」
- 「以后把 KD 当成 KT」
- 「这个词总是识别错」

## 流程

1. 读 `references/glossary.md`。
2. 在解释意图、搜代码、起分支、写回复之前，先套词表。
3. 高置信替换直接做；有冲突就停，问一句，不要猜。
4. 用户确认「以后都这样」时，把映射追加进词表并提交 skill 仓库，不要只改本机。
5. 回复里用校正后的词。不要每条都解释「我把 KD 理解成了 KT」，除非校正会改变方案或涉及钱、权限、生产变更。

## 硬规则

- **默认 `KD` → `KT`**。含 `KD settlement`、`KD 结算`、`接入 KD`。用户上一句里的「KD」几乎总是「KT」被语音认错。
- **不要改 `KDC`**。那是 KTSecret / 凭据中心，不是 KT 的误识别。
- **不要改用户声明的字面量**。若用户说「就是 KD，不是 KT」，保持 KD。
- **不要改代码标识、密钥名、URL、已存在的仓库名**。只校正对用户意图的理解；写代码时仍用仓库里的真实符号。
- **Telegram / 飞机账户** 在 KT 语境里是同一登录因子，不是两个产品。
- 对外产品名仍是 **Kito**。`Keto` / `Kete` 是 Kito 的误识别，不是新品牌。
- **默认 `奇葩` → `七七八八`**（杂项、剩余事项）。不要理解成「做法很荒唐」。用户说「就是奇葩这个词」时保持字面。

## 追加词条

新口误要同时满足：

- 同一会话或后续会话重复出现，或用户明确说「以后都按这个」
- 正确写法在 KT 语境唯一（例如结算域是 `kt-settlement`，不是某个叫 KD 的新系统）

写入格式见词表顶部。改完后按 `skill-installation-workflow` 提交 `KTAIorg/kt-agent-skills`。
